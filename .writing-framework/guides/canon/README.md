# guides/canon/ — Canon Guide Records

## What This Directory Contains

This directory stores **canon records** — the authoritative facts about people, places, events, mechanics, or world-state within a specific project or world. Canon is what is true in the world of the work. It is not interpretation, not implication, and not what has been suggested but not yet committed to. It is what has been decided and must be treated as fixed.

Canon records are the memory of the system across sessions. An agent generating lore, writing NPC dialogue, or continuing a narrative must query canon to avoid inventing contradictions to established fact. A QA agent reviewing output must check it against canon to flag conflicts.

Canon is project-scoped. Facts that are canon for one project are not canon for another. Records in this directory always carry a `project` field.

---

## What Qualifies as Canon

A fact is canon when:
- A human author or authorized agent has explicitly committed to it in a project
- It has been recorded in a source document (world bible, rulebook, authored narrative, session summary) that has been designated canonical
- It has been explicitly confirmed by a project lead when a conflict arose and was resolved

A fact is **not** canon when:
- It was implied by existing canon but never explicitly stated
- It appears in a draft document that has not been approved
- It was generated by an agent without explicit human confirmation
- It is believed to be true by characters in the world (in-world belief is not canon unless the belief matches world-state)
- It conflicts with a more recently established canon record

When in doubt: flag the uncertainty, do not silently assume.

---

## Canon Conflicts

Canon conflicts occur when two canon records assert incompatible facts about the same subject. Conflicts must be **flagged and resolved — never silently overridden**.

Common conflict types:
- **Direct contradiction:** Two records assert opposite facts ("Velrath was destroyed in 412" vs. "Velrath was destroyed in 419").
- **Implicit contradiction:** Two records that are individually coherent but impossible to hold simultaneously ("Kessara has never left the city" + "Kessara was present at the Battle of Golm, which occurred outside the city").
- **Version drift:** An older canon record was valid when written but a later decision made it obsolete, and the old record was not deprecated.
- **Generation conflict:** An agent-generated fact was accepted as story content without being checked against existing canon.

When a conflict is detected:
1. Flag both records with `status: conflict` in their frontmatter.
2. Add `conflict_with: [id-of-other-record]` to both records.
3. Escalate to a human author or project lead for resolution.
4. After resolution, update or deprecate the losing record; mark the winning record as `status: active`.
5. Log the resolution in `guides/decision-records/` for future reference.

Do not generate content that depends on an unresolved canon conflict. Block the task and report the conflict.

## Record Structure

```yaml
---
type: canon
id: canon-[project]-[slug]
title: "[Subject name or description]"
project: [project identifier]
subject_type: person | place | event | object | faction | mechanic | world-state | other
tags: [npc, location, history, ...]
canonical_source: [source document or session reference, if applicable]
established_by: [human author name or "framework"]
established_date: YYYY-MM-DD
last_reviewed: YYYY-MM-DD
status: active | deprecated | conflict | draft
conflict_with: [id, if applicable]
---
```

The body contains:
- **The fact** — stated plainly and completely. No hedging. Canon records do not say "probably" or "it appears that."
- **Context** — the minimum necessary context to make the fact interpretable in isolation
- **Scope and limits** — what this canon record does and does not constrain
- **Related canon** — references to other records that are directly connected

---

## Canon vs. Lore

Canon records state facts. Lore expresses those facts in-world. The distinction matters:

- **Canon record:** "Velrath was destroyed by fire in 412. The fire was set deliberately by the Compact to destroy evidence of the debt ledger."
- **Player-facing lore:** "Three years after the Sundering, Velrath is still burning."
- **DM-facing lore:** "The Compact burned Velrath. The ledger is what they were destroying. [SECRET] The Compact does not know a copy survived."

The canon record is the source. The lore is derived from it. If the lore contradicts the canon, the lore is wrong. If the canon needs to change, the change must be explicitly made to the canon record first, then propagated to dependent lore.

## Querying Canon

Via guide-server MCP (Phase 2 and later):

```
search_guides(type="canon", project="velrath-campaign", query="Kessara history")
get_guide(id="canon-velrath-kessara-background")
related_guides(id="canon-velrath-compact-fire")
search_guides(type="canon", subject_type="event", tags=["412", "fire", "Velrath"])
```

When generating content that involves established world elements, always query canon before writing. If a canon record exists for the subject, the content must be consistent with it. If no record exists, the agent may generate freely — but if the generated content is accepted as story content, a canon record should be created to capture it.

---

## Adding Canon Records

New canon records should be created when:
- A significant fact about a person, place, event, or world-state is established in a session or project document
- A generation conflict is resolved and the resolution needs to be recorded
- A project world bible is imported and its facts need to be indexed

New canon records require human review before being marked `status: active`. Agent-generated facts that a human author has accepted should be recorded by an agent but reviewed by the author before activation.
